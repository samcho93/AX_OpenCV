# 요약 슬라이드(교안) 작성 가이드

강좌 페이지의 **🖼️ 슬라이드 보기 / ⛶ 전체 화면**은 교시별 요약 슬라이드를 보여줍니다.
요약 슬라이드는 `slides/weekN.js` 에 교시마다 작성하며, **교사가 이 슬라이드만 넘기며 50분 수업을 진행할 수 있어야** 합니다.
(작성하지 않은 교시는 강좌 본문에서 자동으로 만들어지지만 길고 장황합니다.)

- **학생용**: 슬라이드 + 퀴즈(정답 공개 버튼) + 실습 시작 코드. 노트는 보이지 않습니다.
- **교사용**: 위 내용 + 아래쪽 **교사용 노트**, 수업 타이머, 발표자 창, 실습 정답 코드 실행 버튼, 퀴즈 정답이 노트에 자동 표시.

## 1. 형식

```js
/* 1주차 요약 슬라이드(교안) */
COURSE.addSlides({
  'w1-1': {
    intro: '<p>표지에서 할 말: 오늘 수업의 동기 부여 한두 문장, 지난 시간과의 연결</p>',
    goalsNotes: '<p>학습 목표 슬라이드에서 할 말 (선택)</p>',
    slides: [
      { title: '컴퓨터는 사진을 어떻게 볼까?',
        points: ['사람: 한눈에 “공 차는 선수”', '컴퓨터: <b>숫자 표</b>만 받음', '숫자에서 규칙을 찾는 것 = <b>영상처리</b>'],
        notes: '<p>교사가 말할 내용(2~5문장). 학생에게 던질 질문, 예상 답, 주의점, 시간 안배.</p>' },

      { title: '픽셀 확대해 보기', example: 0,               // 교시 본문의 code 블록 순서(0부터, norun 포함)
        points: ['공 부분 16×16 픽셀을 20배 확대'],          // (선택) 코드 위 한 줄 요약 1~2개
        notes: '<p>실행 후 결과 창에 마우스를 올려 픽셀 값을 읽게 한다…</p>' },

      { title: '흑백 vs 컬러', table: { head: ['비교', '흑백', '컬러'], rows: [['채널', '1', '3']] }, notes: '…' },

      { title: '영상 = 숫자 격자', points: ['…'], image: 'messi5.jpg', caption: '548×342 = 187,416 픽셀', notes: '…' },

      { title: '핵심만 짚기', points: ['…'], tip: '한 줄 팁(선택)', warn: '한 줄 주의(선택)', notes: '…' },
    ],
    practiceNotes: ['<p>실습 1 진행 요령: 순회하며 확인할 점, 흔한 실수</p>', '<p>실습 2 …</p>'],  // 교시의 practice 순서
    summary: ['오늘 배운 핵심 1', '핵심 2', '핵심 3'],     // 마지막 “정리” 슬라이드의 글머리표
    next: '<p>정리 슬라이드에서 할 말: 다음 교시 예고와 연결 고리</p>',
  },
});
```

자동으로 붙는 슬라이드: **표지 → 학습 목표·수업 흐름 → (작성한 slides) → 실습 과제 각 1장 → 퀴즈 각 1장 → 정리**.
따라서 `slides` 에는 **개념 설명과 예제 슬라이드만** 넣습니다. 실습·퀴즈 슬라이드는 넣지 마세요.

### 슬라이드 종류 (필드로 결정)

| 필드 | 종류 | 설명 |
|---|---|---|
| `points` | 글머리표 | 기본. `image`/`caption` 을 함께 주면 오른쪽에 그림 |
| `example: n` | 예제 코드 | 본문의 n번째 code 블록을 코드 화면 + ▶ 실행 버튼으로 표시. 발표 중에는 오른쪽에 실행 결과 패널이 나타남 |
| `table: {head, rows}` | 표 | 행은 6개 이하 |
| `image` (points 없음) | 큰 그림 | `images/` 의 파일 이름 |
| `tip`, `warn` | 강조 상자 | 슬라이드 아래쪽 한 줄 |

## 2. 작성 원칙 (요약형 교안)

- 슬라이드 수: 교시당 `slides` **8~14장** (자동 슬라이드 포함 전체 15~25장 정도).
- **글머리표는 슬라이드당 3~5개, 한 줄 40자 안팎**. 문장보다 키워드·짧은 구. 코드/함수명은 `<code>`.
- 본문의 설명을 그대로 옮기지 말고 **말로 설명할 뼈대만** 남깁니다. 자세한 설명은 `notes` 로.
- 본문의 **중요한 예제 코드는 대부분 `example` 슬라이드로** 포함합니다(수업 흐름 순서대로). 데스크톱 전용(norun) 코드는 꼭 필요할 때만.
- `notes` 는 교사가 그대로 읽어도 되는 자연스러운 말투 + 괄호 안에 진행 팁. 예:
  `<p>“이 16×16 칸 하나하나가 픽셀이에요.” 결과 창에 마우스를 올려 밝은 칸과 어두운 칸 값을 비교하게 하세요. (약 3분)</p>`
  학생에게 던질 **발문(질문)과 예상 답**, 흔한 실수, 시간 안배를 넣으면 좋습니다.
- 수업 흐름(`schedule`)의 순서·시간과 슬라이드 순서가 어긋나지 않게 구성합니다.
- 프로젝트 주차(4~5주차)는 “단계(Step)별 목표 → 예제 → 점검” 흐름, 팀 활동 안내 슬라이드(진행 방법, 산출물, 체크포인트)를 포함합니다.
- HTML 은 `b strong em code br span` 정도만. 표 셀에도 같은 태그 사용 가능. `<`, `>`, `&` 글자는 `&lt;` `&gt;` `&amp;`.
- 문자열은 작은따옴표/템플릿 문자열 모두 가능. 템플릿 문자열에서는 백틱과 `${` 금지.

## 3. 검증

```bash
node tools/check_slides.js         # 전체
node tools/check_slides.js w2      # 2주차만
```

`example`/`practiceNotes` 인덱스 범위, 글머리표 개수·길이, 누락된 노트 등을 검사합니다.
브라우저에서는 `index.html?role=teacher#w1-1@3` 처럼 열면 해당 교시의 3번째 슬라이드로 바로 이동합니다.
